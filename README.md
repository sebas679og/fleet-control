# 🚚 FleetControl — Fleet Management Platform

FleetControl is a fleet management backend built with a microservices architecture. It consists of **9 autonomous microservices** that communicate with each other and generate their own demo data through a seeder with a fixed seed.

Each team must design, implement, document, and deploy the complete system in their own repository. By the end of the sprint, all teams will have independently built the same platform.

## 🔗 Inter-Service Communication

```
ms-gateway          → routes to all services
ms-dashboard        → consumes: ms-vehicles, ms-routes, ms-fuel, ms-maintenance, ms-alerts
ms-alerts           → consumes: ms-maintenance, ms-fuel, ms-drivers, ms-vehicles
ms-routes           → consumes: ms-vehicles, ms-drivers
ms-maintenance      → consumes: ms-vehicles
ms-fuel             → consumes: ms-vehicles
All domain services → validate JWT issued by ms-auth
```

## 🔑 Demo Data Seeder

### **Configuration Details:**

- **Seed:** Managed via `DEMO_SEED` (default `42`)

- **Days:** Managed via `DEMO_DAYS` (default `90`)

### ⚙️ **Environment Variables**

| Variable              | Description                            | Value             |
|-----------------------|----------------------------------------|-------------------|
| `DEMO_SEED`           | Seed for deterministic data generation | `42`              |
| `DEMO_DAYS`           | Days of history to generate            | `90`              |
| `DEMO_ADMIN_PASSWORD` | Password for the seeded ADMIN user     | `Cambia_Admin123` |

### **Endpoint Mapping**

The following data is generated by the services using the seed defined above:

| Service        | Data Generated                                                                           |
|----------------|------------------------------------------------------------------------------------------|
| ms-vehicles    | Vehicles of the four types and several statuses                                          |
| ms-drivers     | Drivers; 3 with license expiring soon and 1 expired                                      |
| ms-routes      | Completed routes on weekdays and 3 planned routes                                        |
| ms-fuel        | Refuels with consumption consistent with the vehicle type                                |
| ms-maintenance | Plans per vehicle and completed orders; 5 pending orders due within 7 days and 1 overdue |

> ⚠️ The seeder only inserts data if the service tables are empty. Run `docker compose down -v` to regenerate the history from scratch.

## 🐳 Running the Project

### Prerequisites

- Docker & Docker Compose installed
- Java 25 and Maven 3.9+ (only if running outside Docker)

### Setup

1. Clone the repository:
```bash
git clone https://github.com/<your-org>/FleetControl
cd FleetControl
```

2. Copy the template and edit the `.env` file:

```bash
cp .env.example .env
```

> [!IMPORTANT]
> Do **not** commit this file. Add `.env` to your `.gitignore`.

3. Start all services:
```bash
docker compose up --build
```

### Service URLs (local)

| Service       | URL                   |
|---------------|-----------------------|
| Gateway       | http://localhost:8080 |
| Auth          | http://localhost:8081 |
